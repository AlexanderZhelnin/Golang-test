# Сборка

Из корня проекта выполните:

```text
go tool build
```

Команда собирает все четыре варианта. Отдельный вариант задаётся позиционным
аргументом:

```text
go tool build pure
go tool build simd
go tool build pgo
go tool build simd-pgo
```

| Вариант    | GOEXPERIMENT | PGO |
| ---------- | ------------ | --- |
| `pure`     | —            | —   |
| `simd`     | `simd`       | —   |
| `pgo`      | —            | да  |
| `simd-pgo` | `simd`       | да  |

`simd` подключает модуль `calc_simd_experiment.go`; по умолчанию SIMD-код в
бинарь не попадает.

Результат на Windows:

```text
bin/api-pure.exe
bin/api-simd.exe
bin/api-pgo.exe
bin/api-simd-pgo.exe
```

Устанавливать ничего не нужно: инструменты объявлены директивой `tool` в
`go.mod`, живут в `tools/` и обходятся стандартной библиотекой.

# PGO-сборка

Сбор профиля встроен в сборку, отдельной команды нет. Для вариантов `pgo` и
`simd-pgo` `go tool build` автоматически:

1. Собирает тренировочный сервер — без PGO и без `-s -w`.
2. Поднимает его с переменной `API_TEST_PGO_PROFILE`, включающей запись
   CPU-профиля.
3. Обучает профиль на трёх основных эндпоинтах.
4. Останавливает сервер строкой в stdin, чтобы профиль дописался на диск.
5. Собирает финальный бинарь с `-pgo=<профиль>`.


Параметры нагрузки можно переопределить:

```text
go tool build --workers 100 --warmup-seconds 1 --training-seconds 5
```

Нагрузки `/map` и `/mapJSON` циклически используют запрос без параметров и
значения `x/y`: `1`, `25`, `50`, `75`, `100`. Это соответствует диапазону из
существующего JMeter-сценария.


# GOAMD64

Уровень определяется по процессору автоматически и печатается при каждом
запуске. Пробник собирается на `v4`, `v3`, `v2` и запускается: рантайм
проверяет требования уровня при старте и отказывается работать, если процессор
их не выполняет, поэтому первый стартовавший уровень и есть ответ.

Зафиксировать уровень вручную:

```text
go tool build --goamd64 v3
```

# Замер

```text
go tool bench
```

Замеряются все четыре варианта — выбора варианта нет, смысл замера именно в
сравнении сборок между собой. Профили для `pgo`-вариантов снимаются заново, как
и в `build`.
